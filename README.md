# 任务剪切板（Task Clipboard）PWA

一个简约的任务集与待办清单 Web 应用，目标是安装到 Android 手机主屏幕，像轻量级 App 一样打开使用。

> 当前版本：PWA v1（初始安装工程）  
> 技术栈：HTML、CSS、JavaScript、Web App Manifest、Service Worker  
> 部署方式：GitHub Pages 等静态网站托管  
> 状态说明：已生成 PWA 工程文件；真实手机安装、离线行为和完整功能仍需实际部署后测试。

## 功能目标

- 任务集与任务清单
- 任务完成状态与截止日期
- 临期任务集高亮、置顶（以当前实际实现为准）
- 任务集归档与恢复
- 应用内删除/归档确认提示
- PWA 主屏幕安装配置
- Service Worker 应用文件缓存，为离线启动提供基础
- 后续计划：自定义主题、字体上传、字号和间距设置

## 部署到 GitHub Pages

### 1. 创建 GitHub 仓库

1. 登录 GitHub 并创建一个新仓库，例如 `task-clipboard`。
2. 如果希望公开访问，可将仓库设为 Public；请勿提交密码、令牌或个人隐私数据。
3. 将本项目中的文件和 `icons/` 目录上传到仓库根目录，确保 `index.html`、`manifest.webmanifest`、`sw.js` 和 `icons/` 的相对路径不变。

### 2. 启用 GitHub Pages

1. 打开仓库的 **Settings**。
2. 进入 **Pages**。
3. 在 **Build and deployment** 中选择 **Deploy from a branch**。
4. 选择 `main` 分支和 `/(root)` 目录，然后保存。
5. 等待 GitHub Pages 发布完成。页面会显示网站地址，通常形如 `https://<用户名>.github.io/<仓库名>/`。

如果仓库使用其他分支或发布目录，请按实际情况选择。首次发布可能需要等待一会儿。

### 3. 检查部署

使用手机浏览器打开 GitHub Pages 给出的 HTTPS 地址，确认页面能正常显示。若页面无法加载，请检查：

- `index.html` 是否位于选定的发布目录。
- `manifest.webmanifest` 和 `sw.js` 是否与 HTML 中的相对路径一致。
- `icons/` 目录是否已上传。
- 仓库是否已经完成 Pages 发布。

## 在 Android 手机上安装

建议使用最新版 Chrome 或其他支持 PWA 安装的浏览器：

1. 在 Android 手机上打开部署后的 HTTPS 地址。
2. 等页面加载完成后，打开浏览器右上角菜单。
3. 选择 **安装应用**、**安装** 或 **添加到主屏幕**（名称因浏览器版本而异）。
4. 确认安装。
5. 回到手机桌面，点击「任务剪切板」图标启动。

如果没有出现安装选项，可以先通过浏览器菜单使用「添加到主屏幕」。请确认网站通过 HTTPS 访问，且 `manifest.webmanifest` 和图标可以正常加载。

## 更新应用

修改代码后，将修改后的文件提交并推送到 GitHub。GitHub Pages 发布完成后，再用手机访问应用。

Service Worker 会缓存部分应用文件；更新后如果手机仍显示旧版本，可以先关闭应用并重新打开，或在浏览器中刷新页面。必要时清除该网站缓存后重新访问。请注意：清除网站数据可能会影响保存在浏览器本地的任务数据。

## 数据与隐私说明

- 当前版本以浏览器本地存储为主，不提供账号系统或云端同步。
- 本地数据通常不会自动同步到其他浏览器或设备。
- 卸载应用、清除浏览器网站数据或更换手机可能导致本地数据无法继续访问。
- 在加入并验证数据备份/恢复功能前，建议不要把它作为唯一的重要任务记录工具。
- 不要在公开仓库提交个人任务数据、导出的备份文件、访问令牌或其他敏感信息。

## 离线使用说明

项目包含 Service Worker，它会尝试缓存应用外壳文件。首次访问必须联网；成功缓存后，在缓存范围内可尝试离线打开。

离线能力受浏览器、缓存状态和部署配置影响。当前版本尚未在真实 Android 设备上完成全面离线验证，因此请勿将“完全离线可用”视为已经验收的保证。
